## Content types and fields

Four reusable content types drive the whole site, so adding a service or case study never needs a page redesign. Port 4321 suggests an Astro site, so the schema below is written as Astro content collections (Zod); I have not seen your code, so rename fields to match what you already have.

| Content type | Key fields | Used on |
| --- | --- | --- |
| Service | title, order, audience, outcome, deliverables (list), platforms (list), cta | Home, Services |
| Case study | title (result first), employer, role, period, context, goal, actions (list), resultMetric, resultDetail, plainEnglish, tools (list), order, featured | Home, Work |
| Result stat | value (for example 5x), label, employer, source case study | Proof bar, Results at a glance |
| Role | employer, title, start, end, summary | About |

```ts
import { defineCollection, z } from 'astro:content';

const services = defineCollection({
  schema: z.object({
    title: z.string(),
    order: z.number(),
    audience: z.string(),
    outcome: z.string(),
    deliverables: z.array(z.string()),
    platforms: z.array(z.string()),
  }),
});

const caseStudies = defineCollection({
  schema: z.object({
    title: z.string(),
    employer: z.string(),
    period: z.string().optional(),
    context: z.string(),
    goal: z.string(),
    actions: z.array(z.string()),
    resultMetric: z.string(),
    resultDetail: z.string(),
    plainEnglish: z.string(),
    tools: z.array(z.string()),
    order: z.number(),
    featured: z.boolean().default(false),
  }),
});

export const collections = { services, caseStudies };
```

Store the Result stat and Role entries as small data files, and reuse them wherever a number appears, so a result is edited in one place and updates the proof bar, Home and Work together.
